## Implementación

- Dockerfile por repositorio de aplicación, Node 22.18.0, etapas build/runtime y usuario node. .dockerignore excluye secretos/env, Git, dependencias/builds del host, reportes y el next-env.d.ts local.

- depends_on/healthchecks ordenan PostgreSQL → Backend → Frontend. Backend aplica las migraciones Prisma existentes a la BD del contenedor, sin montar el inicializador SQL del Compose antiguo ni operar sobre BD externas.
- El entorno de catálogo es MOCK explícito, Backend NODE_ENV=development y Frontend Next compilado. No activa G6 REAL, no sustituye el contrato externo ni implementa semanas posteriores a la 8.
- Next consulta http://backend:10000. marketplaceApiUrl, usado por los proxies de catálogo y carrito, exige configuración explícita MARKETPLACE_INTERNAL_HTTP_HOST=backend para ese HTTP interno. Conserva HTTPS/loopback y rechaza otros hosts HTTP, credenciales, rutas, query y fragmentos. Las entradas del navegador no deciden el origen del BFF.
- Nuevas pruebas de URL y workflow FE para construir ambos Dockerfiles, levantar el Compose, comprobar readiness real de la BD, home/búsqueda por Next→BFF y carrito anónimo, y detener siempre el proyecto.

Guías: [Backend](https://github.com/Taller-SW-Web/G1-Marketplace-Backend/blob/feat/s1-f006-f007-catalogo/docs/DOCKER-H3.md), [Frontend](https://github.com/Taller-SW-Web/G1-Marketplace-Frontend/blob/feat/s1-f006-f007-catalogo/docs/DOCKER-H3.md).
